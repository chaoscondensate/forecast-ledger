# Forecast Ledger v2.0.1

v2.0.1 is a normative pre-adoption erratum for the
`forecast-envelope/v2` timestamp projection.

## Corrected behavior

`lifecycle_events` is append-only activity metadata. Withdrawal, expiry, and
reaffirmation change a forecast's derived active state but do not change the
recorded belief. Public and sealed envelope projections now exclude
`lifecycle_events`.

Consequently:

- a target built before a lifecycle event is byte-for-byte identical after it;
- target SHA-256 remains unchanged;
- existing RFC 3161 evidence remains verifiable after activity changes;
- all other previously projected forecast fields remain included;
- `forecast-seal/v2` is unchanged;
- the target profile remains `forecast-envelope/v2`.

## Exact vectors

The release adds normative public and sealed target vectors containing
lifecycle events. Each stores the exact RFC 8785 canonical envelope and SHA-256:

- public: `f99fcdc5298be26bee5f38a4c1e742cc96745f2c357727989bcc5f0b5db088c5`;
- sealed: `05968dcf3f03eb5d4c2cbb7afee8588be15cc310e4b0077432fed0f8c6fad773`.

The target conformance runner checks public and sealed projections separately,
proves invariance for `withdrawn`, `expired`, and `reaffirmed`, confirms every
other allowed projection field, and exercises the reference target builder.

## Compatibility boundary

The published v2.0.0 tag and artifacts are unchanged. Their schema, seal vector,
and original projection implementation are frozen by SHA-256 manifests.

The current tools implement only the corrected v2.0.1 projection. No dual
verifier, converter, compatibility bundle, or multi-contract runtime has been
added. Evidence explicitly created under v2.0.0 remains interpretable from the
immutable v2.0.0 tag.
