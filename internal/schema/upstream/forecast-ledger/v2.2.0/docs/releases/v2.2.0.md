# Forecast Ledger v2.2.0

Forecast Ledger v2.2.0 is an intentionally breaking pre-adoption contract
release. It has no converter, dual parser, compatibility bundle, or fallback to
earlier profiles. Implementations must import the schema, semantic rules,
reference tools, fixtures, and vectors from this exact release as one unit.

## Cryptographic profile reset

This release defines one byte contract for each current identifier:

- `forecast-seal/v3` for canonical private plaintext, associated data,
  commitment, and ChaCha20-Poly1305 ciphertext;
- `forecast-key/v3` for a closed protected key file bound to question,
  revision, forecast, and commitment digest;
- `forecast-envelope/v3` for public and sealed recorded-belief targets;
- `forecast-lifecycle/v2` for an ordered lifecycle prefix and its exact head.

Earlier seal, key, envelope, lifecycle, vector-container, and publication IDs
are unsupported inputs. The reference implementation contains no legacy
dispatch or decryption path.

## Retained targets

Forecast integrity now has a closed `retained` state containing only a
`forecast-envelope/v3` target. Activity checkpoints are created directly with a
closed retained `forecast-lifecycle/v2` target. Timestamping advances the same
target to pending or verified without changing any target field.

Checkpoint IDs and recording times are explicit authoring fields. Checkpoint
heads remain unique and cover strictly increasing lifecycle prefixes.

## Evidence and publication sidecars

The new closed `forecast-evidence-index/v1` sidecar inventories every managed
target, RFC 3161 request/response, and retained CA bundle without placing local
filesystem or recovery metadata in the ledger schema. It is canonical RFC 8785
JSON and reconciles ledger declarations, index entries, and exact files.

Publication packages use `forecast-ledger-publication/v3`. Every package has one
ledger and one evidence index, including an empty index for a package with no
evidence. Detached, missing, mismatched, unsafe, or unindexed evidence blocks
package creation. Publication v2 is unsupported.

## Privacy and diagnostics

Public inspection may expose the stored scheme, commitment digest, encryption
algorithm, nonce, ciphertext, and safe logical key hint. It must not expose raw
keys, salts, plaintext, private fields, credentials, or protected paths.

Reference reveal processing publishes stable stage reasons for malformed public
commitments, encoding or algorithm errors, key-file failures, AEAD failure,
commitment-digest mismatch, and authenticated closed-profile mismatch. These
reasons never contain protected content.

## Conformance corpus

The release publishes exact seal, key-file, public/sealed envelope, reveal
continuity, lifecycle-prefix, retained-state, evidence-index, and publication
vectors. Negative cases cover superseded profile IDs, wrong bindings, altered
associated data, digest mismatch, noncanonical bytes, unknown private fields,
detached evidence, and package closure.

The release workflow publishes deterministic source and standalone schema
assets plus `SHA256SUMS`. Commit, annotated-tag, archive, checksum-asset, and
schema digests are recorded only after the actual immutable release exists.
