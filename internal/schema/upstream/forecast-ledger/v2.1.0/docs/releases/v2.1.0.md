# Forecast Ledger v2.1.0

v2.1.0 is an intentionally breaking pre-adoption Forecast Ledger v2 contract
release. Compatibility, conversion, dual verification, and floating aliases are
not provided. Import the schema, semantic validator, reference crypto, target
builder, fixtures, and vectors from this exact tag as one unit.

This release addresses the confirmed LC1 lifecycle-integrity and S1 sealed
private-field findings reported during downstream CLI dogfooding.

## LC1: lifecycle chronology and integrity

- A lifecycle event `effective_at` cannot precede its forecast's
  `forecasted_at`.
- Event `recorded_at` cannot precede its own `effective_at` or the forecast's
  `recorded_at`.
- Unique IDs, non-decreasing effective time, append-only recording time, and
  active/inactive transitions remain normative semantic checks.
- `lifecycle_events` remains excluded from public and sealed
  `forecast-envelope/v2` projections.
- New closed `forecast-lifecycle/v1` targets bind question ID, forecast ID,
  forecast-envelope SHA-256, one complete ordered event prefix, and its head.
- Optional append-only `activity_checkpoints` retain integrity and RFC 3161
  evidence for named lifecycle heads. Later events leave earlier checkpoints
  valid and make their coverage partial.
- Exact vectors cover withdrawal, reaffirmation, multiple checkpoints, prefix
  alteration, event deletion, reordering, and wrong forecast binding.

A retained checkpoint can detect mutation or deletion within its covered
prefix. Deleting every event, checkpoint, target, evidence package, and external
copy removes the evidence that an event previously existed.

## S1: optional sealed private text

The closed `forecast-seal/v2` private bundle now permits exactly
`representations`, `rationale`, `key_factors`, and `comment`. Only a non-empty
`representations` collection is required. The other fields are independently
optional, and absence remains different from an explicitly supplied empty
string or empty array.

A revealed forecast requires `representations` and its revealed commitment.
Reference reveal logic adds only private fields authenticated by the bundle and
rejects invented optional fields. Presence vectors cover every optional-field
combination, explicit empty values, missing representations, unknown
properties, and altered reveal presence.

## Diagnostics

- Missing properties are reported by exact JSON Pointer.
- An absent property receives no fabricated source location.
- Existing invalid nodes and syntax failures retain bounded line and column.
- Diagnostics redact cryptographic failures and never include protected values,
  source excerpts, keys, salts, credentials, or unrestricted filesystem paths.

## Compatibility decision

The repository's normal rule would assign a new major and protocol identifier
to these changes. This exact release follows the commissioned pre-adoption v2
cutover instead: contract version `2.1.0`, retained `forecast-seal/v2`, retained
`forecast-envelope/v2`, and new `forecast-lifecycle/v1`. Every earlier tag and
artifact remains immutable. Use its tagged code to verify its historical bytes.

## Verification and assets

The release workflow validates the Draft 2020-12 schema, all valid and invalid
fixtures, semantic chronology, seal-presence vectors, public and sealed envelope
vectors, lifecycle targets and tamper vectors, diagnostic safety, frozen-tag
hashes, lint, and compilation before publishing.

The GitHub Release contains a deterministic source archive, standalone schema,
JSON and YAML examples, and `SHA256SUMS` generated from the exact annotated tag.
